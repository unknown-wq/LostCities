# building6 — «Глубинносланцевая башня»

Документ описывает переработку шаблона `building6` в моде `lostbuildings` (Fabric, MC 26.2).
Все пути указаны от корня репозитория.

---

## 1. Что было и что стало

### Было

`building6` — единственное здание в наборе, которое строится из глубинного сланца
(варианты `deepslate` = `deepslate_tiles` + `cracked_deepslate_tiles` и
`deepslate_rubble`). При этом **собственных частей у него не было вообще**:

```json
"parts": [
  {"top": false, "part": "building5_1"},   // чужая геометрия
  {"top": false, "part": "building5_2"},
  {"top": false, "part": "building5_3"},
  {"top": false, "part": "building5_4"},
  {"top": true,  "part": "top1x1_2"},      // общая «шапка»
  {"top": true,  "part": "top1x1_3"},
  {"top": true,  "part": "top1x1_4"},
  {"top": true,  "part": "top1x1_5"}
]
```

То есть `building6` был буквально копией `building5` с другой палитрой: те же четыре
этажных среза, та же общая крышка `top1x1_*`. Внутри — пустые залы, лестница из
одной вертикальной лестницы-стремянки (`ladder`), ни одного сундука, ни одного спавнера.
В реальной генерации это давало серую коробку из 15–17 разных блоков (см. §4).

### Стало

Восемь собственных частей + полностью переписанная локальная палитра здания.
Все части — 16×16, ровно 6 срезов (обязательное требование движка: `FLOORHEIGHT = 6`).

| Файл (`.../lostcities/parts/`) | Условие выбора | Что даёт |
|---|---|---|
| `building6_cellar.json` | `cellar: true` | Подвал-хранилище: глухие стены из глубинносланцевого кирпича, хранилище за решёткой с сундуками и бочками, котельная с чугунными агрегатами и цепями, стеллажные проходы, спавнер `hardmobs` |
| `building6_ground.json` | `ground: true` | Первый этаж: витринное остекление во всю высоту, трёхблочный вход с чиселед-перемычкой, подиум ресепшена с прилавком, кадки с растениями, служебные помещения за перегородкой |
| `building6_1.json` | средние этажи | Опен-спейс: ковровые зоны, сетка из 18 столов, переговорная со стеклянными перегородками, кухонный уголок, стеллажи вдоль стены |
| `building6_2.json` | средние этажи | Кабинетный этаж: центральный коридор с ковровой дорожкой, шесть отдельных кабинетов с дверными проёмами, у каждого своя обстановка |
| `building6_3.json` | средние этажи, `range: "2,16"` | Разрушенный этаж: пробитый фасад, обвалившийся потолок, завалы щебня, паутина, спавнеры `hardmobs` и `easymobs`, полуразвалившаяся перегородка |
| `building6_4.json` | средние этажи, `range: "1,4"` | Архив/серверная: щелевые окна, восемь рядов стеллажей вдоль центрального прохода, хранилище за решёткой, машинный отсек с цепями |
| `building6_5.json` | средние этажи, `range: "3,16"` | Зимний сад / лаундж: остекление в пол с внутренним ограждением, две приподнятые клумбы, зеркальный бассейн в бортике, светильники и глоустоун в потолке |
| `building6_top.json` | `top: true` | Крыша: парапет с балюстрадой, лестничная будка над шахтой, машинный блок с водяным баком, сарай с сундуком, антенная мачта на скошенном постаменте с маяком-глоустоуном |

Плюс в `buildings/building6.json`:

* собственная палитра из **30 символов** (было 2);
* `mincellars: 1`, `maxcellars: 1` — у здания всегда ровно один подвал
  (это позволило сделать пол подвала сплошным, без шахты в фундамент);
* условия выбора частей (`ground` / `cellar` / `top` / `range`), чтобы шестиэтажный
  экземпляр не выглядел одним и тем же срезом, отштампованным шесть раз.

## 2. Что видит игрок

### Снаружи

Здание читается как брутальный офисный/административный блок. Фасад собран по
вертикальному ритму, повторяющемуся на каждом этаже:

```
y+5   deepslate_bricks + карниз из ступеней (тень)
y+4   глухой ряд глубинного сланца — перемычка окна
y+3   стекло
y+2   стекло
y+1   глухой ряд — подоконник
y+0   пояс из полированного чёрного камня (blackstone)
```

По углам — двухблочные «квадры» из blackstone, идущие снизу доверху; они визуально
делят коробку на четыре пилона. На уровне потолка каждого этажа по всему периметру
идёт **карниз** — ступени `polished_blackstone_brick_stairs[half=top]`, развёрнутые
приподнятой половиной внутрь, так что снаружи получается затенённая выемка, а
сквозной дыры в стене нет. Углы карниза закрыты `chiseled_polished_blackstone`.

Первый этаж отличается сознательно: остекление идёт на три блока вместо двух
(витрина), над ним — сплошной пояс из `chiseled_polished_blackstone`, а в северной
стене трёхблочный проём входа.

Разные этажи имеют разный рисунок окон: широкие ленты (опен-спейс), узкие простенки
(кабинеты), одиночные щели (архив), остекление в пол (лаундж), выбитая стена
(разрушенный этаж). Поэтому шестиэтажный экземпляр не выглядит однородным.

### Внутри, снизу вверх

**Подвал.** Всегда есть, ровно один. Глухие стены, ни одного окна. В восточной части —
хранилище за решёткой (решётка приоткрыта посередине, внутрь можно войти): два сундука
с лутом, две бочки с лутом, слиток железа на постаменте, светильник душ. В западной
части — котельная: железные блоки, решётки, свисающие цепи. Центр занимают стеллажные
проходы. Здесь же спавнер `hardmobs` — движок при этом ещё и повышает сложность мобов
с высотой (`BuildingRole.hardMobChance`).

**Первый этаж.** Через трёхблочный вход попадаешь в лобби с полом в шахматную клетку
из `polished_deepslate` и `smooth_basalt`. Напротив входа — ресепшен: ступень вверх
на подиум, прилавок из верхних плит, за ним бочка с лутом и офисный хлам. По бокам
входа — кадки с землёй и растениями. За перегородкой — служебная зона на два
помещения: стеллажи, сундук, верстак/печь, бочка, спавнер.

**Средние этажи** — пять разных вариантов, движок выбирает случайно с учётом высоты:

* *Опен-спейс* — ковровые зоны, сетка столов (забор + нажимная плита, приём из
  оригинальных частей мода), переговорная в углу со стеклянными перегородками и
  большим столом, кухонный уголок, стеллажи.
* *Кабинеты* — коридор по центру с ковровой дорожкой, три кабинета слева и три
  справа, дверные проёмы, в каждом кабинете свой набор мебели; в одном спавнер.
* *Разрушенный этаж* — восточный фасад выбит (смесь треснувшей плитки и воздуха),
  потолок над восточной половиной обвалился, пол под провалом засыпан щебнем,
  вокруг паутина и обломки плит; перегородка развалилась; два спавнера; уцелел один
  светильник душ на цепи.
* *Архив* — щелевые окна, восемь рядов стеллажей (полки, бочки, кафедры,
  резные книжные шкафы) вдоль центрального прохода, хранилище за решёткой в углу,
  машинный отсек с железными блоками и цепями.
* *Лаундж* — остекление в пол с внутренним ограждением из глубинносланцевых
  стенок, две приподнятые клумбы с землёй и цветами, зеркальный бассейн 2×2 в
  бортике из полного блока (вода никуда не растекается), диванные столы, глоустоун,
  утопленный в потолок.

**Лестница.** Настоящая, одинаковая во всех частях, поэтому стыкуется этаж в этаж:
двухблочный марш идёт вдоль южной стены, пять ступеней в срезах 1–5 и шестая — в
срезе 0 следующего этажа. Поднявшись, вы выходите в общий проход, который в каждой
части оставлен свободным. Проём в перекрытии огорожен стенкой из глубинносланцевого
кирпича. Марш и проём проверены программно на всех 30 сочетаниях «нижняя часть →
верхняя часть» (см. §5).

**Крыша.** Марш выводит в лестничную будку с дверным проёмом. Снаружи — парапет:
сплошной пояс, над ним балюстрада из стенок, по углам чиселед-блоки. На площадке:
машинный блок с водяным баком в железном коробе, технический сарай с сундуком и
бочкой, площадка вентиляции из плит и антенная мачта — железные прутья на скошенном
постаменте (ступени, поднятой половиной внутрь) с глоустоуном-маяком наверху и
цепями-растяжками.

## 3. Лут и мобы

Использована уже существующая машинерия, ничего нового в движке не добавлялось:

* `C` — сундук с условием `chestloot` (условие уже учитывает этаж и роль здания);
* `&` — бочка с тем же условием `chestloot` (новый символ, но старое условие);
* `1` / `4` — спавнеры `easymobs` / `hardmobs`; движок сам повышает `easymobs`
  до `hardmobs` тем чаще, чем выше этаж.

В сгенерированном четырёхэтажном экземпляре получилось 8 сундуков, 50 бочек
и 8 спавнеров (часть бочек — это стеллажи `s`, они без лута, просто мебель).

## 5. Ограничения и что пришлось урезать

**Обязательные ограничения формата** (проверены по коду движка, не угаданы):

* Часть — строго 16×16 и ровно 6 срезов. `BuildingEngine.FLOORHEIGHT = 6`,
  `BuildingPiece.clearHeight` рассчитывает объём под расчистку исходя из этого же
  числа. Часть другого размера не встанет в стопку.
* Символ `' '` (воздух) и `structure_void` означают «оставить как есть», а не
  «поставить воздух». Для наземных этажей это безопасно (`Foundation` заранее
  расчищает объём), для подвала — тоже (`BuildingEngine.carveCellar` вырезает
  срез перед записью).
* Каждый символ должен разрешаться во **всех** стилях, с которыми здание может
  быть построено (`standard`, `standard_border`, `desert`, `snowy`, `swamp`,
  `outside`). Проверено скриптом: для каждого стиля берётся пересечение символов
  внутри каждой группы `randompalettes` (движок выбирает из группы случайно), плюс
  символы локальной палитры здания. Нерезолвящихся символов — ноль. Из общих
  палитр сознательно не используется `;` (печь с углём) — его нет в
  `default_desert`.
* Сумма весов в списке `blocks` палитры должна быть ≥ 128, иначе
  `CompiledPalette` бросает исключение при загрузке. Все новые записи это соблюдают.

**Что не получилось сделать так, как хотелось:**

1. **Настоящие сквозные проломы между этажами.** Каждый срез — это пол (срез 0) и
   потолок (срез 5), и части выбираются независимо друг от друга. Дыра в потолке
   разрушенного этажа упирается в сплошной пол этажа сверху, так что вместо
   провала на два уровня получается ниша глубиной в блок плюс завал на своём полу.
   Синхронизировать дыру с соседним срезом можно было бы только через
   `belowpart`, но `ConditionMatcher` его сознательно игнорирует
   (задокументировано в самом классе как отложенное упрощение). Оставил как есть.
2. **Выступающие карнизы и подоконники.** Габарит здания — ровно 16×16, это весь
   чанк-ячейка; наружу вынести нечего. Карниз сделан «в плоскости стены»
   ступенями `half=top`, развёрнутыми внутрь: снаружи получается затенённая
   выемка. Это работает, но это тень, а не свес.
3. **Лестница идёт всеми маршами в одну сторону.** Классический разворот на
   180° на каждом этаже потребовал бы, чтобы части чередовались, а движок
   выбирает их случайно и независимо. Ядро лестницы поэтому одинаково во всех
   восьми частях: пять ступеней в срезах 1–5 плюс шестая в срезе 0 следующей
   части. Это стыкуется всегда, но выглядит как «ножничная» лестница, а не как
   лестничная клетка с площадками.
4. **Проём в перекрытии не огорожен полностью.** Ограждение стоит только с
   северной стороны шахты (`x = 3..6`, `z = 12`). Замкнуть его нельзя: с запада
   и востока стоят сами ступени, а сплошное ограждение по `z = 12` перекрыло бы
   проход вдоль этажа. Упасть в проём можно, но падать — шесть блоков на марш
   этажом ниже.
5. **Ровно один подвал.** Поставил `mincellars: 1, maxcellars: 1`. Иначе при
   двух подвалах нижний марш упирался бы в сплошной пол верхнего подвала, а при
   нуле подвалов в полу первого этажа осталась бы дыра в фундамент. Диапазон
   этажей (2–6) при этом не трогал: его всё равно выбирает `CityLayout` до вызова
   движка, и `minfloors`/`maxfloors` здания в этом пути игнорируются.
6. **Часть бочек пустые.** Символ `s` (стеллаж) случайно разрешается в
   `barrel` / `lectern` / `chiseled_bookshelf` / `bookshelf` — это мебель, лута
   в ней нет. Лут только у `C` (сундук) и `&` (бочка). В переписи выше это видно
   как большое число `barrel` при восьми `chest`.
7. **Семя мира в dev-сервере невоспроизводимо.** `level-seed=1337` в
   `run/server.properties` в этой сборке не даёт одинаковый мир между запусками,
   поэтому «до» и «после» замерены на разных мирах (по три реальных экземпляра
   в каждом), а не на одной и той же клетке. Сравниваются нормализованные
   метрики: число типов блоков, число контейнеров, число спавнеров.

**Чего не трогал:** ничего в `1.21/` (read-only источник порта) и ничего в
`engine/**` — задача чисто по данным. Ни одного нового Java-класса, ни одной
правки логики.

## 6. Как посмотреть в игре

1. Запустить сервер:
   ```sh
   cd lostbuildings && JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64 \
     /opt/gradle-9.6.1/bin/gradle runServer --no-daemon
   ```
2. В игре: `/locate structure lostbuildings:lost_city`, затем телепорт к городу.
3. `building6` попадается примерно на одном лоте из восьми (в
   `citystyles/citystyle_common.json` у него вес `0.2`; веса восьми зданий в
   `LostCityConfig` равны). Стиль и биом на выбор здания не влияют — палитра
   здания перекрывает стилевую, поэтому дом всегда глубинносланцевый.
4. **Как узнать снаружи:** единственное здание в городе, целиком собранное из
   `deepslate_tiles`. Ищите тёмно-серую коробку с чёрными угловыми пилонами,
   горизонтальным поясом из полированного чёрного камня на уровне каждого
   перекрытия и антенной с ярким блоком глоустоуна на крыше.
5. Внутри: вход — трёхблочный проём с чиселед-перемычкой; лестница — вдоль
   стены, по которой идёт лестничный марш; она доводит до самой крыши, до
   лестничной будки. Подвал есть всегда, вход в него — тот же марш вниз.
6. Быстрая проверка через RCON без клиента: скрипты
   `rcon.py` / `mcworld.py` / `census6.py` в рабочем каталоге сессии делают
   `locate` → `forceload` → `save-all flush` → `stop` → чтение чанков с диска.
   **Важно:** останавливать сервер только командой `stop` и дожидаться её
   завершения, прежде чем трогать `run/world`.
